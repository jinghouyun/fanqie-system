# 二次开发指南

## 0. 先判断你要改哪一层

| 你想做的事 | 改哪里 | 走哪条路线 |
| --- | --- | --- |
| 改界面、改文案、改接口地址、加页面 | `decompiled/uniapp-www/` | 路线 A |
| 加权限、接推送/支付等原生 SDK、改启动流程 | `decompiled/java/` 或 `decompiled/apktool/` | 路线 B / C |
| 只改 Manifest、换图标、改硬编码字符串 | `decompiled/apktool/` | 路线 C |

## 路线 A：还原 uni-app 工程

### A1. 直接用现成工程（推荐）

**`uniapp-project/` 已经是还原好的 uni-app Vue 3 工程，不用再手工还原。**

```
uniapp-project/
├── App.vue              应用入口（含版本更新检查横幅）
├── main.js              标准 uni-app Vue3 入口
├── pages.json           6 个页面路由（已含标题与 navigationStyle: custom）
├── manifest.json        原应用 manifest
├── api/index.js         网络请求 + 账户 store（导出 request / auth）
├── pages/               6 个页面（模板 + <script setup> + <style scoped>）
│   ├── login/login.vue
│   ├── home/home.vue
│   ├── tomato/tomato.vue
│   ├── duoduosou/duoduosou.vue
│   ├── duoduosou/movie.vue
│   └── account/account.vue
└── *.render.txt         该页面还原前的原始渲染函数（人工校对用）
```

步骤：

1. HBuilderX → 新建项目 → uni-app → **Vue 3** 版本 → 默认模板。
2. 用 `uniapp-project/` 覆盖新项目根目录。
3. 运行到手机 / 模拟器；确认无误后云打包或离线打包。

### A2. 想自己重跑一遍还原

```bash
python tools/restore_vue.py
```

脚本读取 `decompiled/uniapp-www/__UNI__34AA080/www/app-service.js`，把每个组件的 `render()` 渲染函数反解成 `<template>`，输出到 `uniapp-project/`。改了清洗规则后可以反复重跑。

### A3. 渲染函数 → 模板 的映射关系

编译产物与模板语法的对应（脚本已实现，手工校对时可对照）：

| 编译产物 | 模板语法 |
| --- | --- |
| `createElementVNode("view", {...}, [...])` | `<view ...>...</view>` |
| 三元 + `createCommentVNode("", true)` | `v-if` / `v-else` |
| `renderList(list, (item, i) => ...)` | `v-for="(item, i) in list"` |
| `withDirectives(node, [[vModelText, x]])` | `v-model="x"` |
| `normalizeClass([...])` | `:class="[...]"` |
| `normalizeStyle({...})` | `:style="{...}"` |
| `withModifiers(fn, ["stop"])` | `@click.stop="..."` |
| `toDisplayString(x)` / `createTextVNode` | `{{ x }}` / 文本节点 |
| `"a" + toDisplayString(x)` | `a{{ x }}` |
| `renderSlot($slots, "default")` | `<slot />` |

### A4. 关键业务信息

- 接口基址：`http://47.116.57.181:3001`
- 请求头：`Content-Type: application/json`、`x-app-version: 1.1.0`、`Authorization: Bearer <token>`
- 请求实现：`plus.net.XMLHttpRequest`，超时 15 秒
- Token 存储：`uni.getStorageSync("auth_token")`；用户信息：`uni.getStorageSync("auth_user")`
- 退出登录：清掉上面两个 key

## 路线 B：Gradle 工程

1. Android Studio（Koala+）打开 `decompiled/java/`。
2. 用 JDK 17 + AGP 8.10.1（工程已配好）。
3. 同步后会大量报"找不到符号"，按包补依赖，常用的有：
   - `io.dcloud` 的 uni-app SDK（`android-gif-drawable`、`weex`、`uts-runtime` 等已带 .so，需要 aar）
   - `androidx.*`（core / appcompat / fragment / lifecycle / constraintlayout）
   - `com.facebook.fresco:imagepipeline`（带 native so）
   - `com.squareup.okhttp3`、`com.squareup.okio`
   - Kotlin 协程 `kotlinx-coroutines-android`
4. 补完后 `Build > Make Project` 即可。

> 提示：如果只做原生小改动，路线 C 通常更省时间。

## 路线 C：改 smali 后回编译

### C1. 常见改动位置

| 目标 | 文件 |
| --- | --- |
| 权限、组件、包名 | `apktool/AndroidManifest.xml` |
| 应用名 / 硬编码字符串 | `apktool/res/values/strings.xml`，或 smali 中的 `const-string` |
| 接口地址 | smali 中的 `const-string`，或路线 A 里的 `app-service.js` |
| 图标 | `apktool/res/mipmap-*/` |

### C2. 回编译命令

```bash
java -jar apktool.jar b decompiled/apktool -o dist/番茄系统_mod.apk
zipalign -p -f -v 4 dist/番茄系统_mod.apk dist/aligned.apk
apksigner sign --ks my.keystore --ks-key-alias fanqie --out dist/番茄系统_signed.apk dist/aligned.apk
apksigner verify dist/番茄系统_signed.apk
```

### C3. 排错

| 现象 | 处理 |
| --- | --- |
| 安装后闪退，logcat 报壳相关 | APK 带加固壳，去掉 `assets/39285EFA.dex` 与 `lib/*/lib39285EFA.so` 相关的壳代码，或改用路线 A 重新打包 |
| `apktool b` 报资源错 | 删除 `apktool/APKTOOL_DUMMY` 之类无用文件；不要动 `apktool.yml` |
| 签名后安装失败 | 先卸载原包（签名不同）；确认 `zipalign` 在 `apksigner` 之前执行 |
| 加固壳导致无法改 smali | 用路线 A：uni-app 层重新打包，绕开加固 |
